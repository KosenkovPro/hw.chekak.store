# hw.chekak.store

**ЧёКак Железо** (hw.chekak.store) — мониторинг железа с упором на комбайн из датчиков, видеопамяти (VRAM), температур и нагрузки на компоненты.

Этот документ — подробный разбор и сравнение **четырёх популярных диспетчеров задач для Windows**, которые лежат рядом в рабочем пространстве (`../TaskExplorer`, `../systeminformer`, `../RustWTM`, `../gputaskman`). Разбор сделан по их исходному коду и README в локальных клонах, поэтому утверждения привязаны к конкретным версиям (см. [Методика и версии](#10-методика-версии-и-источники)).

> Готовый вариант этой же таблицы в браузере: **[comparison.html](comparison.html)** — откройте файл двойным щелчком.

Общая картина:

- **System Informer** — база и «движок». Максимум низкоуровневого доступа (драйвер, kernel-объекты, кучи, драйверы) и максимум «классики»: Process Explorer, старый Process Hacker, SI.
- **Task Explorer** — лучший «взгляд внутрь процесса» глазами. Панели, DLL-инъекция, редактор памяти, удалёнка, Linux.
- **RustWTM** — единственный из четырёх, кто не просто показывает, а **управляет**: governor, лимиты, правила, блокировки, порты, Telegram-бот, AI, MCP.
- **gputaskman** — единственный, кто отвечает на вопрос **«кто именно съедает видеопамять»** и **«какая модель это»**. Терминальный, read-only, узкоспециализированный.

## 3. Подробно по каждому проекту

### 3.1 System Informer — [winsiderss/systeminformer](https://github.com/winsiderss/systeminformer)

**Суть.** Продолжение линейки Process Hacker / Process Explorer от Winsider Seminars & Solutions. Не «красивый монитор», а системный инструмент: собственный kernel-драйвер `systeminformer.sys` (KPH) даёт то, чего не даёт обычный Win32 API.

**Что умеет (по коду и README):**

- **Дерево процессов** с календарём запуска, группами, вкладками колонок (`chcol.c`), скрытыми процессами (`hidnproc.c`), поиском скрытых/уже завершённых процессов.
- **Панели процесса** (по именам исходников): `thrdlist/thrdstk/thrdshstk` (потоки и стеки), `memlist/memedit/memsrch/memmod/memprot` (память, редактор, поиск строк), `modlist/modprv` (модули), `hndllist/hndlprp/hndlmenu` (хэндлы), `netlist/netstk/netsup` (сокеты), `prpgsrv/srvcr/srvctl` (службы: создание и управление), `prpgtok` (токен), `prpgenv` (окружение), `prpgmem`, `prpgjob` (Job-объекты), `prpghndl`, `prpgmod`, `prpgthrd`, `procmtgn` (mitigations), `prpgvdm`, `prpgwmi`, `prpgperf`, `prpgstat`, `thrdctx`, `heapinfo` (кучи), `gdihndl` (GDI/USER), `ntobjprv` (NT-объекты), `pagfiles`, `miniinfo/mdump/kdump` (дампы памяти), `dbgcon` (отладочная консоль), `findobj` (поиск объектов), `delayload/delayhook` (delay-load hook и инъекция), `procgrp`, `sessprp/usrlist` (сессии и пользователи).
- **Графики и обзор системы**: `syssccpu`, `sysscmem`, `sysscio` + страницы производительности по процессам/дискам/сети/GPU (`mwpgdev/mwpgnet/mwpgproc/mwpgsrv`).
- **Плагины (12)**: `WindowExplorer` (окна, UIA, DWM-атрибуты, дерево окон), `ExtendedTools` (диск/сеть, требует админа), `ExtendedServices`, `NetworkTools`, `HardwareDevices` (оборудование), `AgentTools`, `DotNetTools`, `OnlineChecks`, `Updater`, `UserNotes`, `ToolStatus`, `ExtendedNotifications`.
- Портативность: можно запускать с флешки, настройки — рядом с exe (`SystemInformer.exe.settings.xml`).

**Особенности и ограничения.**

- Глубина NT недостижима для остальных: heap-сегменты, пулы ядра, VDM, mitigation-политики, локальные драйверные стеки.
- Нет ни CLI, ни скриптования, ни удалённого режима, ни AI/MCP — это чистый интерактивный GUI.
- Видеопамять по процессам есть только через `ExtendedTools` и без «модельного» анализа.

**Когда брать:** разбор инцидентов, «кто держит файл/хэндл», реверс-инженерия поведения процесса, работа с драйверами и службами.

### 3.2 Task Explorer — [DavidXanatos/TaskExplorer](https://github.com/DavidXanatos/TaskExplorer)

**Суть.** Qt 6 GUI поверх PHlib из Process Hacker и собственной сборки `systeminformer.sys`. Прямой конкурент System Informer, но с современным UI и заметно расширенной кроссплатформенностью.

**Что умеет (по README и CHANGELOG):**

- **Панели процесса** (каталог `GUI/TaskInfo`): Thread (+ stack view), Memory (с редактором памяти и поиском по строкам), Handles, Sockets (с скоростью передачи и псевдо-UDP по ETW), Modules (выгрузка и **инъекция DLL**), Token, Environment, Windows, GDI, .NET, Heap, Job, Security, Debug, Sandboxie (SbieView), Process.
- **Системные панели** (`GUI/SystemInfo`): CPU, RAM, Disk, Network, **GPU**, DNS-кэш, RPC-эндпоинты, Services, Drivers, System info.
- **Инструменты:** поиск окон перетаскиванием «прицела», Run / Run as, создание службы, окно драйвера с обновлением DynData, онлайн-апдейтер (по модели Sandboxie), mini-dump helper, свой редактор разрешений (secureable objects), мини-дампы.
- **Linux — нативный бэкенд, а не слой совместимости:** `/proc`, `sock_diag`, systemd через D-Bus, стеки через libdwfl с `file:line`. Появились панели **Control Group** (cgroup: cpu/memory/io/pids и лимиты) и **Security** (AppArmor/SELinux, seccomp, capabilities, no-new-privs), график **Pressure (PSI)**, вкладка **Daemons**, реальные ELF core-дампы. Windows-панели Token/Job/GDI/.NET/RPC/Pool/Atom на Linux выключены на уровне сборки.
- **Удалённый мониторинг (2.0.0):** `TaskServer` + `TaskRemote`, кроссплатформенные Windows↔Linux соединения, несколько машин сразу, кластерный режим, безопасная аутентификация и хранение учётных данных, обнаружение серверов в локальной сети, **Window Agents** для чужих пользовательских сессий. Требует сертификат поддержки (магазин автора).
- **Wine-интеграция на Linux:** имена Windows-процессов, хэндлы, окна, токены, Windows PID.

**Особенности и ограничения.**

- **GPL-3.0** — если результат пойдёт в коммерческий продукт, код нельзя закрыть под проприетарной лицензией. Для MIT-проекта вроде hw.chekak.store это главный юридический риск при копировании.
- Нет ни CLI, ни MCP/AI, ни автоматизации: всё через GUI.
- Видеопамять/движки GPU показаны, но без per-process разбора моделей и без аккуратной работы со счётчиками WDDM (нет `Local`/`Non-local` семантики, нет оценки `Paged`).

**Когда брать:** если нужен именно GUI-мониторинг «всё про процесс» на Windows **и** Linux, или удалённый мониторинг нескольких машин, или вы готовы принять GPL.

### 3.3 RustWTM — [RustWTM/RustWTM](https://github.com/RustWTM/RustWTM)

**Суть.** «Диспетчер задач, который сохраняет твой ПК отзывчивым». Три исполняемых файла: GUI `rustwtm.exe`, CLI `wtm.exe`, служба `wtm-service.exe` (LocalSystem, IPC `\\.\pipe\RustWTM`, протокол 17). Проект на Rust (egui), опциональный аппаратный провайдер — .NET 8+.

**Что умеет.**

- **Процессы:** список / дерево / Apps (одна строка на приложение — действует на все его процессы), раскладки колонок (Basic/CPU/Memory/IO/Network/Diagnostics), панель деталей, быстрые фильтры (CPU 5%+, RAM 512 MiB+, процессы «последние N минут», GPU/диск-активные, пользовательские vs службы), заморозка списка (F6), поиск, группировка по пользователю.
- **Производительность:** графики CPU (по каждому логическому процессору), памяти, GPU, сети, диска; **отдельная страница на каждое устройство** (диски, адаптеры, GPU) с температурами диска и GPU, NVMe wear, MAC-адресами, Wi-Fi; timeline 1/2/5 минут с курсором, зумом, метками событий и честными «пробелами» в данных; App history, Users, Services, Network, Events, Startup apps; спецификация железа и управление установленными приложениями.
- **Диагностика «почему не отвечает»:** статус *Not responding*, **Analyze wait chain** между процессами с поиском дедлоков, «почему не завершается» (защита Windows, античит-драйвер, другие держатели).
- **Инспекция:** модули с проверкой подписи (Authenticode + каталог), токен/права/SID/группы, переменные окружения, открытые хэндлы (файлы/ключи реестра), карта памяти с кучами и стеками, окна процесса, поиск хэндла или DLL по всем процессам, «прицел» для поиска процесса по окну.
- **Управление:** завершение, дерево процессов, suspend/resume, приоритет, affinity, EcoQoS, жёсткие лимиты CPU и памяти через Job Objects, запуск задачи, перезапуск Explorer.
- **Governor-сервис (уникальная функция):** ступенчатое понижение приоритета → EcoQoS → жёсткий CPU-cap при длительной перегрузке; **memory guard** (сброс working set при RAM > 90%); защита приложения переднего плана; правила по имени/пути с условиями (`cpu_above`, `memory_above_mb`, `gpu_above`) и действиями (включая `kill`); бюджеты CPU/RAM на приложение (`node.exe: 2 ядра`, `zen.exe: 8 ГБ`); kill-list и «паника» (Ctrl+Shift+K); **блок-лист через IFEO** (программа не стартует вообще); режим игры (снижение приоритета фоновых приложений, High performance, откат при выходе); резервирование «спасательного» ядра; долгосрочная статистика в SQLite с линейным трендом и R² (хронический CPU / рост памяти → утечка); обнаружение «роя» копий процесса.
- **Порты и сеть:** все слушающие порты с владельцем и числом клиентов, распознавание ~75 портов dev-инструментов (Vite, Next.js, PostgreSQL, Redis, Docker, Ollama), «освободить порт» (убивает владельца), ETW-байты по программам, закрытие IPv4 TCP-соединения, **блокировка сети программы двумя правилами Windows Firewall**.
- **Дополнительно:** монитор Docker-контейнеров (Compose-проекты, лимиты, порты, health, логи), анализ диска (дерево папок с размерами, 200 крупнейших файлов, разбивка по типам), поиск владельца файла, обновление Store/WinGet с проверкой SHA-256, **Telegram-бот** (статусы, действия с телефона), датчики и охлаждение (температуры, RPM, питание, напряжение, такты, ручной duty, кривые, пресеты Quiet/Balanced/Performance), гибридные CPU с P/E-ядрами, **встроенный AI-ассистент** (11 провайдеров + Ollama/LM Studio, ключи под DPAPI, секреты маскируются, доступ к управлению не даётся), **MCP-сервер** (`wtm mcp`) с 20+ инструментами, режим `--allow-control`.
- **Интеграция с Windows:** может заменить штатный диспетчер по Ctrl+Shift+Esc (машинная настройка), 27 языков.

**Особенности и ограничения.**

- **Только Windows**, только x64. Это не кроссплатформенный инструмент.
- Служба работает от **SYSTEM**: серьёзный поверхность атаки и источник непреднамеренных последствий. Поэтому по умолчанию включён **dry-run**, а enforcement надо включать руками.
- Статус — early release (0.35.0); часть аппаратных функций (запись оборотов вентиляторов) честно помечена как «требует валидации на каждом железе».
- Для GPU показывает движки и память, но не делает того, что делает gputaskman: не разбирает VRAM на «веса / KV-кэш / compute» и не распознаёт модели.

**Когда брать:** нужен «умный» диспетчер с автополитикой, автоматизацией, интеграцией с AI-агентами и/или удалённым управлением с телефона.

### 3.4 gputaskman — [shanselman/gputaskman](https://github.com/shanselman/gputaskman)

**Суть.** «htop для того, что внутри GPU, а не только насколько он заполнен». Терминальный монитор, который склеивает счётчики GPU с распознаванием рантаймов и LLM-моделей.

**Что умеет.**

- **Устройство:** VRAM (total/used/free), загрузка, температура, питание, такты (SM/GFX), активность памяти, PCIe-трафик, вентилятор, троттлинг, версии драйвера/CUDA, PCIe-генерация/ширина, compute capability, power/clock limits, performance state.
- **Процесс:** dedicated VRAM (Local), GPU-доступная системная RAM (Shared/Non-local), оценка **Paged** = `max(commit − local − non-local, 0)`, активность по движкам (3D/Compute/Copy/Video), распознанные рантаймы (CUDA, HIP, Vulkan, Direct3D, ggml, ONNX Runtime, Metal).
- **Аккуратный учёт памяти:** используются `Local Usage`/`Non Local Usage`, а не `Dedicated Usage`, чтобы не считать одну и ту же поверхность DWM трижды; при превышении суммы строк над ёмкостью адаптера полоса нормализуется, а легенда остаётся «сырой».
- **LLM-разбор:** по GGUF-заголовкам определяется *тип* модели (LLM / decision / embedding / speech / diffusion), считаются веса, ожидаемая KV-цена и размеры буферов; поддержаны llama.cpp/llama-server, Ollama, LM Studio, vLLM, Foundry Local, stable-diffusion.cpp, Handy, Whisper/ONNX-подобные. У каждой модели показан **уровень доказательства**: `api` / `mapped` / `cmdline` / `path-arg` / `installed`; `path-arg` не считается подтверждением.
- **Локальные API рантаймов:** опрос собственных слушающих портов (`/props`, `/slots`, `/metrics`, `/v1/models`, `/api/ps`, `/api/v1/models`, `/api/v0/models`), ключ llama-server используется как bearer и никогда не пишется в JSON; запросы — только к localhost.
- **Сценарии работы:** TUI, `--once` (текст), `--json`, `--list-gpus`, `--gpu N`, `diff` (сравнение двух снимков по VRAM с учётом переиспользования PID), `record` (JSONL-журнал), `replay` (офлайн-воспроизведение с ускорением 0.5×–4×), `summary` (средние/пики по записи), `--no-host` (WSL), `--no-system`.
- **Платформы:** Windows (NVIDIA/AMD/Intel через WDDM, ADL/AMD SMI, NVML), Linux (NVML; DRM `amdgpu`/`i915`/`xe`), WSL (счётчики Windows-хоста через interop и сопоставление контекстов `vmwp.exe`), macOS Apple Silicon (Metal + `footprint`).
- **Строгая честность данных:** неизвестное значение — это `null`/`N/A`, а не ноль; в JSON есть `started_at`, чтобы переиспользование PID не давало ложных «изменений».

**Особенности и ограничения.**

- **Только чтение** и **только терминал**: ни дерева процессов, ни управления, ни графического UI.
- Всё, что связано с GPU, детально; всё, что связано с CPU/RAM/диском/сетью — обзорно (колонки RAM/CPU%, панель System).
- Проект young (0.4.4) и сам честно перечисляет невалидированные пути: AMD/Intel на нативном Linux, `xe`, TCC-карты без WDDM, несколько GPU, WSL-сопоставление.
- В выгрузке JSON/скриншотах видны пути, аргументы командной строки, имена моделей и локальные порты — перед публикацией нужно вычищать.

**Когда брать:** главный вопрос — «кто съел VRAM и что это за модель», обучение/инференс на своей машине, ночные тренировки, multi-GPU, расследование «почему LLM тормозит».

## 4. Сравнение по глубоким осям

### 4.1 GPU и видеопамять

| Аспект | System Informer | Task Explorer | RustWTM | gputaskman |
|---|---|---|---|---|
| Общая загрузка GPU | есть | есть | есть, отдельная страница на GPU | есть, 8 графиков истории |
| VRAM по процессам | через `ExtendedTools` | отдельная GPU-панель | dedicated/shared по процессам | **подробно: Local/Shared/Paged** |
| Движки (3D/Compute/Copy/Video) | частично | частично | **да, с поиском по типам движков** | **да, с дельтой загрузки** |
| Температура/питание/троттлинг GPU | через плагин | частично | да | да |
| Защита от двойного счёта (DWM и т. п.) | нет | нет | нет | **да: Local/Non-local, нормализация полос** |
| Multi-GPU | частично | частично | страница на каждый GPU | **да, свой блок на каждый адаптер** |
| LLM-модели (веса/KV-кэш) | нет | нет | нет | **да, с уровнями доказательства** |

### 4.2 Память и «тяжёлые» сценарии

- **System Informer / Task Explorer** — показывают *структуру* памяти процесса (регионы, кучи, PEB/TEB, private/commit), умеют её редактировать и искать по строкам.
- **RustWTM** — даёт *системную* картину (composition, standby/modified, kernel pools, hardware reserved), ловит утечки по тренду и умеет освобождать RAM (trim) и ставить лимиты.
- **gputaskman** — RAM только как контекст: working set и CPU% на фоне GPU, с явной оговоркой, что это не private working set как в диспетчере Windows.

### 4.3 Дерево процессов и инспекция

Здесь разрыв максимальный. System Informer и Task Explorer дают десятки низкоуровневых панелей и глубокую работу с драйверами/хэндлами. RustWTM даёт современную «рабочую» инспекцию (детали, ожидание, подписи модулей, карта памяти, безопасность токена) и три режима списка. gputaskman процессами не занимается вообще — он про GPU.

### 4.4 Управление и привилегии

| Модель | Кто так умеет |
|---|---|
| Ручное управление процессами | все три GUI-проекта |
| Глубокое управление (хэндлы, память, DLL, службы) | System Informer, Task Explorer |
| Автоматическое управление по правилам | **только RustWTM** |
| Ограничение ресурсов (CPU/RAM) | **только RustWTM** (Job Objects) |
| Блокировка запуска программ | Task Explorer (драйвер), **RustWTM (IFEO)** |
| Служба под SYSTEM | **только RustWTM** |

### 4.5 Автоматизация, скрипты, AI

- **RustWTM** — единственный с CLI, конфигом TOML, правилами, MCP-сервером и встроенным AI-ассистентом; плюс Telegram-бот как удалённый интерфейс.
- **gputaskman** — единственный с «аналитической» автоматизацией: `diff`/`record`/`replay`/`summary` дают честную аналитику «что изменилось с VRAM» без GUI.
- **System Informer / Task Explorer** — автоматизации нет; у Task Explorer есть удалённый сервер, но это не скриптование, а мониторинг.

### 4.6 Кроссплатформенность

Здесь выигрывают не те, о ком обычно думают: **gputaskman** работает на Windows/Linux/WSL/macOS, **Task Explorer** — на Windows и Linux, **System Informer** и **RustWTM** — только Windows. При этом RustWTM компенсирует отсутствие Linux собственными средствами автоматизации.

### 4.7 Зрелость и риски

| Проект | Зрелость | Главный риск |
|---|---|---|
| System Informer | Высокая, аномально стабильная база | Плотный UI, нет автоматизации, драйвер требует доверия |
| Task Explorer | Высокая, активно развивается | **GPL-3.0** + платная удалёнка (сертификат) |
| RustWTM | Средняя (0.35.0, early release) | Служба SYSTEM, dry-run по умолчанию, часть железа не валидирована |
| gputaskman | Средняя (0.4.4), TUI | Неполная валидация на AMD/Intel/TCC/multi-GPU, приватность выгрузок |

## 6. Что взять на вооружение для hw.chekak.store

Цель hw.chekak.store — «комбайн из датчиков, VRAM, температур и нагрузки на компоненты». Ни один из четырёх не делает этого целиком, но у каждого есть заимствуемый кусок:

1. **Семантика счётчиков GPU — из gputaskman.** Разделять `Local Usage` и `Non Local Usage`, не складывать `Dedicated Usage` (иначе одна поверхность DWM считается трижды), показывать неизвестное как «нет данных», а не ноль, и подписывать каждое число источником (WDDM / NVML / ADL / DRM).
2. **Модель «измерено / выведено / оценено» — из gputaskman.** Три уровня уверенности с явной пометкой источника — редкая и очень правильная практика: мониторинг железа часто врёт, если не показывать, откуда взялась цифра.
3. **Дерево процессов и панели — из System Informer / Task Explorer.** Даже минимальная реализация (процесс → потоки → память → хэндлы → модули) резко отличает hw.chekak.store от «просто показывает счётчики».
4. **Политики и лимиты — из RustWTM.** Идея «наблюдатель, который умеет вмешиваться по правилам» (порог CPU/RAM/GPU + действие) — естественное продолжение комбайна; реализовывать её стоит в dry-run по умолчанию.
5. **Форматы данных и сравнение — из gputaskman (`diff`/`record`/`summary`) и RustWTM (JSON-вывод CLI).** Для проекта, который будет отдавать данные наружу (API/бот), machine-readable вывод — обязателен.
6. **Плагины и открытый API — из System Informer.** Расширяемость важнее закрытого набора виджетов: датчики и правила у пользователей должны добавляться без правки ядра.
7. **Юридическая оговорка.** Код Task Explorer под GPL-3.0 — **не копировать** в MIT-проект hw.chekak.store без переписывания по своему дизайну. RustWTM, System Informer и gputaskman — MIT, по ним можно брать идеи и отдельные фрагменты с указанием авторства.
