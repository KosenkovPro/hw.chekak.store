01Коротко: кто есть кто

Четыре инструмента решают разные задачи и почти не пересекаются функционально.

MIT

System Informer

winsiderss/systeminformer — «глубокий» системный инструмент: собственный kernel-драйвер, десятки панелей, плагины.

  • Дерево процессов, скрытые процессы, поиск по объектам
  • Потоки, стеки, кучи, хэндлы, пулы ядра, драйверы
  • Редактор памяти, delay-load hook, работа со службами
  • 12 плагинов, портативный запуск

Слабое место: нет CLI, автоматизации, удалёнки и AI.

GPL-3.0

Task Explorer

DavidXanatos/TaskExplorer — Qt 6 GUI поверх PHlib и драйвера System Informer.

  • ~20 панелей процесса, включая Memory Editor и инъекцию DLL
  • Нативный Linux: cgroup, LSM, PSI, systemd, ELF core-дампы
  • Удалённый мониторинг: TaskServer / TaskRemote, кластер, Window Agents
  • Wine-интеграция на Linux

Слабое место: copyleft-лицензия и отсутствие скриптования.

MIT

RustWTM

RustWTM/RustWTM — GUI + CLI + служба под SYSTEM: единственный, кто вмешивается в систему по правилам.

  • Governor: троттлинг, memory guard, лимиты CPU/RAM, kill-list, IFEO-блок
  • Правила и конфиг TOML, порты, Docker, Telegram-бот
  • AI-ассистент (11 провайдеров + локальные) и MCP-сервер
  • 27 языков, замена Ctrl+Shift+Esc

Слабое место: только Windows, служба SYSTEM, статус early release.

MIT

gputaskman

shanselman/gputaskman — «htop для GPU»: отвечает на вопрос «кто съел видеопамять и что это за модель».

  • VRAM по процессам: Local / Shared / Paged, движки 3D-Compute-Video
  • Температуры, питание, такты, троттлинг, PCIe, multi-GPU
  • Распознавание LLM-моделей, весов и KV-кэша с уровнями доказательства
  • Windows, Linux, WSL, macOS; diff/record/replay

Слабое место: только терминал и только чтение.

03Подробно по каждому проекту

Особенности, сильные стороны и ограничения — то, что важно при выборе.

System Informer MIT github.com/winsiderss/systeminformer

Продолжение линейки Process Hacker / Process Explorer от Winsider Seminars & Solutions. Не «красивый монитор», а системный инструмент: собственный kernel-драйвер systeminformer.sys (KPH) даёт то, чего не даёт обычный Win32 API.

Что умеет

  • Дерево процессов с календарём запуска, группами, вкладками колонок, скрытыми процессами, поиском скрытых и уже завершённых процессов.
  • ~30 панелей процесса (по именам исходников): потоки и стеки, память + редактор + поиск строк, модули, хэндлы, сокеты, службы (создание и управление), токен, окружение, Job-объекты, mitigation-политики, кучи, GDI/USER, NT-объекты, пулы ядра, сессии и пользователи, дампы памяти и мини-дампы, отладочная консоль, delay-load hook.
  • Обзор системы: графики CPU, памяти, ввода-вывода, страницы производительности по процессам, дискам, сети и GPU.
  • 12 плагинов: WindowExplorer (окна, UIA, DWM-атрибуты), ExtendedTools (диск/сеть, нужен админ), ExtendedServices, NetworkTools, HardwareDevices, AgentTools, DotNetTools, OnlineChecks, Updater, UserNotes, ToolStatus, ExtendedNotifications.
  • Портативный запуск с флешки, настройки рядом с exe.

Ограничения

  • Нет ни CLI, ни скриптования, ни удалённого режима, ни AI/MCP — только интерактивный GUI.
  • Видеопамять по процессам — только через ExtendedTools, без модельного анализа.

Брать для: разбор инцидентов, «кто держит файл/хэндл», работа с драйверами и службами, реверс поведения процесса.

Task Explorer GPL-3.0 github.com/DavidXanatos/TaskExplorer

Qt 6 GUI поверх PHlib из Process Hacker и собственной сборки systeminformer.sys. Прямой конкурент System Informer, но с современным UI и заметно расширенной кроссплатформенностью.

Что умеет

  • Панели процесса: Thread + stack view, Memory (редактор памяти и поиск строк), Handles, Sockets (скорость передачи, псевдо-UDP по ETW), Modules (выгрузка и инъекция DLL), Token, Environment, Windows, GDI, .NET, Heap, Job, Security, Debug, Sandboxie.
  • Системные панели: CPU, RAM, Disk, Network, GPU, DNS-кэш, RPC-эндпоинты, Services, Drivers, System info.
  • Инструменты: поиск окон перетаскиванием «прицела», Run / Run as, создание службы, окно драйвера с обновлением DynData, онлайн-апдейтер, mini-dump helper, свой редактор разрешений.
  • Linux — нативный бэкенд, а не слой совместимости: /proc, sock_diag, systemd через D-Bus, стеки через libdwfl с file:line. Панели Control Group (cgroup: cpu/memory/io/pids и лимиты) и Security (AppArmor/SELinux, seccomp, capabilities), график Pressure (PSI), вкладка Daemons, реальные ELF core-дампы. Windows-панели Token/Job/GDI/.NET/RPC/Pool/Atom на Linux выключены на уровне сборки.
  • Удалённый мониторинг (2.0.0): TaskServer + TaskRemote, кроссплатформенные соединения, несколько машин, кластерный режим, аутентификация, обнаружение серверов в локальной сети, Window Agents для чужих сессий. Требует сертификат поддержки.
  • Wine-интеграция на Linux: имена процессов, хэндлы, окна, токены, Windows PID.

Ограничения

  • GPL-3.0 — код нельзя закрыть под проприетарной лицензией; для MIT-проекта это главный юридический риск при копировании.
  • Нет CLI, MCP/AI и автоматизации — всё через GUI.
  • VRAM и движки показаны, но без семантики Local/Non-local и без оценки Paged.

Брать для: GUI-мониторинг «всё про процесс» на Windows и Linux, удалённый мониторинг нескольких машин.

RustWTM MIT github.com/RustWTM/RustWTM

«Диспетчер задач, который сохраняет твой ПК отзывчивым». Три исполняемых файла: GUI rustwtm.exe, CLI wtm.exe, служба wtm-service.exe (LocalSystem, IPC \\.\pipe\RustWTM, протокол 17). Rust + egui, опциональный аппаратный провайдер на .NET 8+.

Процессы и инспекция

  • Режимы List / Tree / Apps (одна строка на приложение — действует на все его процессы), раскладки колонок, панель деталей, быстрые фильтры, заморозка списка (F6).
  • Графики CPU (по каждому логическому процессору), памяти, GPU, сети, диска; отдельная страница на каждое устройство с температурами, NVMe wear, MAC-адресами, Wi-Fi.
  • Timeline 1/2/5 минут с курсором, зумом и честными «пробелами» в данных; App history, Users, Services, Network, Events, Startup apps, спецификация железа.
  • Диагностика: статус «Not responding», Analyze wait chain между процессами с поиском дедлоков, «почему не завершается» (защита Windows, античит-драйвер).
  • Модули с проверкой подписи, токен и права, переменные окружения, открытые хэндлы, карта памяти с кучами и стеками, окна процесса, поиск хэндла или DLL, «прицел» для поиска процесса по окну.

Governor-сервис — уникальная функция

  • Ступенчатое понижение: приоритет → EcoQoS → жёсткий CPU-cap при длительной перегрузке; откат при восстановлении.
  • Memory guard: при RAM > 90% сбрасываются working sets фоновых приложений (ничего не закрывается).
  • Защита приложения переднего плана (protect_foreground) и резерв «спасательного» ядра.
  • Правила по имени/пути с условиями cpu_above, memory_above_mb, gpu_above и действиями (включая kill).
  • Бюджеты CPU/RAM на приложение, kill-list и «паника» (Ctrl+Shift+K), блок-лист через IFEO, режим игры с откатом.
  • Долгосрочная статистика в SQLite с линейным трендом и R²: хронический CPU и растущая память помечаются как утечка.
  • Порты: владелец, клиенты, распознавание ~75 dev-портов, «освободить порт»; ETW-байты по программам, закрытие TCP, блокировка сети двумя правилами Firewall.
  • Монитор Docker-контейнеров, анализ диска, обновление Store/WinGet с проверкой SHA-256, Telegram-бот, датчики и охлаждение (duty, кривые, пресеты), гибридные CPU с P/E-ядрами.

AI и интеграции

  • Встроенный ассистент: 11 провайдеров + Ollama/LM Studio, ключи под DPAPI, секреты маскируются, доступ к управлению не выдаётся.
  • MCP-сервер wtm mcp: 20+ инструментов, в режиме --allow-control — управление процессами с проверкой create_time.
  • Может заменить штатный диспетчер по Ctrl+Shift+Esc; 27 языков.

Ограничения

  • Только Windows x64.
  • Служба работает от SYSTEM — это серьёзная поверхность атаки; поэтому по умолчанию включён dry-run.
  • Статус early release; часть аппаратных функций (запись оборотов вентиляторов) не валидирована.
  • GPU показывается, но без разбора VRAM на «веса / KV-кэш / compute» и без распознавания моделей.
gputaskman MIT github.com/shanselman/gputaskman

«htop для того, что внутри GPU, а не только насколько он заполнен». Терминальный монитор, склеивающий счётчики GPU с распознаванием рантаймов и LLM-моделей.

Устройство и процессы

  • VRAM (total/used/free), загрузка, температура, питание, такты SM/GFX, активность памяти, PCIe, вентилятор, троттлинг, версии драйвера и CUDA, PCIe-генерация, compute capability, power/clock limits.
  • По процессам: dedicated VRAM (Local), GPU-доступная системная RAM (Shared), оценка Paged = max(commit − local − non-local, 0), активность движков (3D/Compute/Copy/Video), рантаймы (CUDA, HIP, Vulkan, Direct3D, ggml, ONNX Runtime, Metal).
  • Аккуратный учёт памяти: используются Local Usage/Non Local Usage вместо Dedicated Usage, чтобы не считать одну поверхность DWM трижды; при превышении суммы над ёмкостью адаптера полоса нормализуется, легенда остаётся «сырой».
  • По потокам: полоса потоков, 60-семпловые истории CPU и RAM, топ по RAM и CPU.

LLM-разбор

  • По GGUF-заголовкам определяется тип модели: LLM, decision, embedding, speech, diffusion.
  • Считаются веса, ожидаемая KV-цена и размеры compute-буферов.
  • Поддержаны llama.cpp / llama-server, Ollama, LM Studio, vLLM, Foundry Local, stable-diffusion.cpp, Handy, Whisper/ONNX-подобные.
  • У каждой модели показан уровень доказательства: api, mapped, cmdline, path-arg, installed; path-arg подтверждением не считается.
  • Локальные API рантаймов опрашиваются на своём localhost: /props, /slots, /metrics, /v1/models, /api/ps. Ключ llama-server используется как bearer и нигде не сохраняется.

Сценарии и платформы

  • TUI, --once, --json, --list-gpus, --gpu N, diff, record, replay, summary, --no-host, --no-system.
  • Windows (WDDM, NVML, ADL/AMD SMI), Linux (NVML; DRM amdgpu/i915/xe), WSL (счётчики Windows-хоста + сопоставление контекстов vmwp.exe), macOS Apple Silicon (Metal + footprint).
  • Неизвестное значение — это null/«нет данных», а не ноль; в JSON есть started_at, чтобы переиспользование PID не давало ложных изменений.

Ограничения

  • Только чтение и только терминал: ни дерева процессов, ни управления, ни GUI.
  • CPU/RAM/диск/сеть — обзорно (колонки RAM и CPU%, панель System).
  • Проект young (0.4.4): AMD/Intel на нативном Linux, xe, TCC-карты, multi-GPU и WSL-сопоставление авторы сами помечают как невалидированные.
  • В JSON и скриншотах видны пути, аргументы командной строки, имена моделей и локальные порты — перед публикацией нужно вычищать.

Память

  • System Informer / Task Explorer — показывают структуру памяти процесса (регионы, кучи, PEB/TEB, private/commit), умеют её редактировать и искать по строкам.
  • RustWTM — даёт системную картину (composition, standby/modified, kernel pools, hardware reserved), ловит утечки по тренду, умеет trim и ставить лимиты.
  • gputaskman — RAM только как контекст: working set и CPU% на фоне GPU, с явной оговоркой, что это не private working set диспетчера Windows.

Дерево процессов и инспекция

Разрыв максимальный: System Informer и Task Explorer дают десятки низкоуровневых панелей и глубокую работу с драйверами и хэндлами. RustWTM даёт современную «рабочую» инспекцию (детали, ожидание, подписи модулей, карта памяти, токен) и три режима списка. gputaskman процессами не занимается вообще — он про GPU.

Автоматизация, скрипты, AI

  • RustWTM — единственный с CLI, конфигом TOML, правилами, MCP-сервером и встроенным AI-ассистентом; плюс Telegram-бот как удалённый интерфейс.
  • gputaskman — единственный с «аналитической» автоматизацией: diff/record/replay/summary дают честный ответ «что изменилось с VRAM» без GUI.
  • System Informer / Task Explorer — автоматизации нет; у Task Explorer есть удалённый сервер, но это мониторинг, а не скриптование.

Кроссплатформенность

Здесь выигрывают не те, о ком обычно думают: gputaskman работает на Windows/Linux/WSL/macOS, Task Explorer — на Windows и Linux, а System Informer и RustWTM — только на Windows. При этом RustWTM компенсирует отсутствие Linux собственными средствами автоматизации.

06Что взять на вооружение для hw.chekak.store

Цель проекта — комбайн из датчиков, VRAM, температур и нагрузки. Ни один из четырёх не закрывает её целиком, но у каждого есть заимствуемый кусок.

  • Семантика счётчиков GPU — из gputaskman. Разделять Local Usage и Non Local Usage, не складывать Dedicated Usage (иначе одна поверхность DWM считается трижды), показывать неизвестное как «нет данных», а не ноль, и подписывать каждое число источником: WDDM / NVML / ADL / DRM.
  • Модель «измерено / выведено / оценено» — из gputaskman. Уровень уверенности с указанием источника: мониторинг железа врёт, если не показывать, откуда взялась цифра.
  • Дерево процессов и панели — из System Informer / Task Explorer. Даже минимальная связка «процесс → потоки → память → хэндлы → модули» отличает монитор от «просто набора счётчиков».
  • Политики и лимиты — из RustWTM. Наблюдатель, который умеет вмешиваться по правилам (порог CPU/RAM/GPU → действие), — естественное продолжение комбайна; реализовывать в dry-run по умолчанию.
  • Форматы данных — из gputaskman (diff/record/summary) и RustWTM (JSON из CLI). Если данные пойдут наружу через API или бота, machine-readable вывод обязателен.
  • Плагины и открытый API — из System Informer. Расширяемость важнее закрытого набора виджетов.
  • Юридическая оговорка. Task Explorer под GPL-3.0 — не копировать в MIT-проект hw.chekak.store без переписывания по своему дизайну. Остальные три — MIT, идеи и фрагменты можно брать со ссылкой на авторов.
